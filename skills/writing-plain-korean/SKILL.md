# 사람이 쓰는 한국어로 쓰기

## 핵심

한국어 개발자가 회의에서 동료에게 **입으로 말하듯** 쓴다. 원문 문서의 개념어는 옮기지 말고, 그 말이 가리키는 **일(누가 무엇을 하는지)**으로 바꿔 쓴다.

원문에 있는 말이라는 사실은 그 말을 쓸 이유가 되지 않는다. 원문이 번역투로 쓰였다면, 요약도 번역투가 된다.

## 쓰는 순서

1. **원문을 읽고 덮는다.** 원문 문장을 보면서 쓰지 않는다. 무엇을 말하려는지 먼저 한 줄로 정리한다.
2. **문장을 "누가 무엇을 한다"로 쓴다.** 주어는 사람, 프로그램, 파일처럼 손에 잡히는 것이다. "판정은 인증 서버가 한다"보다 "인증 서버가 허락할지 말지 정한다"가 낫다.
3. **이름이 꼭 필요하면 코드에 있는 이름을 쓴다.** 코드 식별자, 경로, 명령, 널리 쓰이는 기술 용어(API, 토큰, 프록시, 역할(role), scope, 사이드카)는 그대로 쓴다. 덜 알려진 용어는 처음 나올 때 한 줄로 풀어 준다.
4. **다 쓴 뒤 명사구를 하나씩 읽고 묻는다.** "이 말을 회의에서 그대로 하나?" 아니면 바꾼다.

## 자주 나오는 말과 바꾸는 법

| 원문에 자주 나오는 말 | 이렇게 쓴다 |
|---|---|
| 축 (dimension) | 소속, 기준. 예: "부서별로" |
| 표면 (surface) | API, 화면, 엔드포인트 |
| 층 1, 층 2 / 두 층 | 첫 번째 확인, 두 번째 확인 / 두 단계 |
| 판정 | 허락할지 정한다, 확인한다 |
| 집행 | 막는다, 적용한다 |
| 거처, 자리 | 어디에 두는지, 위치 |
| 주체, 주체 표현 | 사용자, 사용자 정보 |
| 표식 | 표시, 설정 값 |
| 분담 | 나눠 맡는다 |
| 이양 | 넘긴다 |
| 펼친다, 전개한다 | 바꿔서 적용한다 |
| 수렴한다 | 맞춰진다, 반영된다 |
| 데이터 접근점 | 데이터를 읽는 곳(예: 조회 서버) |
| 부여 단위 | 권한을 줄 때 고르는 단위 |
| 게이트 | 막는 곳, 확인 |
| 어휘 | 이름, 목록 |
| 판 (panel) | 창, 패널. 예: "지도 위에 뜨는 챗봇 창" |

표에 없는 말도 같은 방식으로 판단한다. 영어 개념을 한자어 한두 글자로 옮긴 말은 거의 다 이 경우다.

## 예시

원문: "행 단위 필터의 집행은 데이터 접근점(조회 서버)이 한다. 판정 근거는 인증 서버, 집행은 데이터 접근점이라는 분담이다."

나쁜 요약: "행 필터는 데이터 접근점인 조회 서버가 집행하고, 인증 서버와 분담한다."

좋은 요약: "부서별로 행을 거르는 일은 조회 서버가 합니다. 인증 서버는 '이 사용자는 A 부서 소속'이라는 정보만 넘겨 주고, 조회 서버가 그 정보로 행을 거릅니다."

## 실제 글에서 나온 문장

| 원문 개념어를 옮긴 문장 | 풀어 쓴 문장 |
|---|---|
| "판정은 인증 서버가 하고 집행은 사이드카가 합니다" | "인증 서버가 허락할지 정하고, 사이드카가 허락되지 않은 요청을 막습니다" |
| "소속 축으로 행을 거릅니다" | "부서별로 행을 거릅니다" |
| "데이터 접근점(조회 서버)이 집행합니다" | "데이터를 읽는 조회 서버가 행을 거릅니다" |
| "주체 표현에 attributes를 싣습니다" | "사용자 정보 헤더에 소속 부서를 담습니다" |
| "규칙의 거처는 둘로 나뉩니다" | "권한 정보는 두 군데에 나눠 둡니다" |
| "모듈이 규칙을 보고하면 등록부가 수렴합니다" | "모듈이 규칙을 알려 주면 인증 서버가 60초 안에 반영합니다" |
| "엔진 표면을 그대로 통과시킵니다" | "엔진 API를 BFF가 그대로 넘겨 줍니다" |
| "기능은 엔진 scope 묶음으로 펼쳐집니다" | "인증 서버가 기능 권한을 엔진 scope로 바꿔서 확인합니다" |
| "화면 표면은 제품과 설정 두 층입니다" | "화면은 `app/`과 `admin/` 두 곳에 나눠 둡니다" |
| "이양하는 것은 화면이 아니라 role입니다" | "고객사에 넘길 때는 화면을 옮기지 않고 role을 줍니다" |
| "층 단위 게이트는 두지 않습니다" | "관리 화면 전체를 막는 권한은 따로 만들지 않습니다" |

## "A가 아니라 B"는 B만 쓴다

영어 "not A but B"를 옮긴 문장이 자주 나온다. 읽는 사람은 A를 떠올린 적이 없는데, 글이 A를 먼저 꺼내서 부정한다. B만 말한다.

| 이렇게 쓰게 된다 | 이렇게 쓴다 |
|---|---|
| "효과는 린터 점수가 아니라 눈에 보이는 결과로 잽니다" | "효과는 눈에 보이는 결과로 잽니다" |
| "`no-console`을 error가 아닌 warn으로 둡니다" | "`no-console`은 warn으로 둡니다" |
| "문제라기보다 아직 답하지 않은 질문입니다" | "아직 답하지 않은 질문입니다" |

A를 남기는 때는 하나다. 읽는 사람이 이미 A라고 생각하고 있거나 그렇게 오해할 만할 때다. 예를 들어 사용자가 "Mac이 화면을 끈 것 같다"고 했다면, "Mac이 끈 것이 아니라 모니터 쪽에서 신호가 끊겼습니다"는 필요한 문장이다.

## 사실을 더하지 않는 꾸미는 말은 지운다

"실제로", "정상적으로", "확실히", "제대로", "정확히", "~자체가", "핵심은" 같은 말은 문장을 강조하지만 사실을 더하지 않는다. 지워 보고 뜻이 같으면 지운다.

| 이렇게 쓰게 된다 | 이렇게 쓴다 |
|---|---|
| "실제로 가까운 시각에 기록이 없었습니다" | "가까운 시각에 기록이 없었습니다" |
| "케이블 교체는 정상적으로 반영되었습니다" | "케이블 교체가 반영되었습니다" |
| "모니터 자체가 원인일 가능성이 높습니다" | "모니터가 원인일 가능성이 높습니다" |
| "제안의 핵심은 다음과 같습니다. 단계를 줄입니다." | "단계를 줄이자고 제안합니다." |

뜻을 더하는 부사(다시, 이미, 먼저, 따로, 한 번 더)는 그대로 쓴다. "실제 브라우저에서 확인했다"처럼 테스트 환경과 구분하는 말도 사실이므로 남긴다.

## 흔한 실수

- **원문 소제목을 그대로 가져온다.** "규칙의 거처는 둘로 나뉜다"처럼 쓰게 된다. 소제목이 가리키는 내용을 문장으로 쓴다.
- **문체만 고치고 단어는 둔다.** 해요체로 바꿔도 "집행은 두 층이에요"는 여전히 읽히지 않는다.
- **괄호에 원어를 달고 끝낸다.** "축(dimension)"은 풀이가 아니다. 무엇인지 설명해야 한다.

## 기계로 검사하기

이 스킬 폴더의 `scripts/lint_korean.py`가 정규식으로 셀 수 있는 것을 찾는다. 위 표의 개념어, "A가 아니라 B" 꼴, 꾸미는 말, em-dash와 가운뎃점, 본문의 "~함/~임" 종결, "~의"가 이어지는 구, "되어지다", "~에 있어서", 40어절이 넘는 문장이다. 코드, 표, 인용, 따옴표 안 문구는 건너뛴다.

```bash
python3 scripts/lint_korean.py 문서.md      # 걸린 것이 있으면 exit 1
python3 scripts/lint_korean.py --self-test
```

plain-korean 플러그인으로 설치했다면 훅이 이 검사를 자동으로 돌린다. `.md` 파일을 쓰거나 고치면 새로 쓴 부분을 검사해 바로 알려 주고, 답변이 끝나면 걸린 것을 적어 두었다가 다음 답변을 쓰기 전에 알려 준다. 막지는 않는다.

린터는 뜻을 모른다. 걸린 것 중 업무 용어(예: 품질 "판정")나 꼭 필요한 대조는 그대로 둔다.
